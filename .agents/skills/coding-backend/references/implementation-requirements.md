# Backend implementation requirements

Apply only the groups relevant to the assigned scope; skip unrelated groups, do not expand scope.

| Group | How to apply |
|---|---|
| Content/CMS | CRUD per the real entities; draft, published, scheduled and unpublish when requested. Public APIs never expose drafts/future content; preview needs permission and must not be publicly cached. Scheduling uses a defined timezone; jobs must be re-runnable without double-publishing. |
| SEO data | Use existing fields or add per spec: `seo_title`, `meta_description`, slug, share image, indexability. Fall back to real content, never overwrite values the editor entered; frontend/SSR responses and the sitemap use the same rules. |
| URL/slug | Consistent normalization rules; uniqueness at the right scope (domain/tenant/language per the real model), with a database constraint to handle concurrent creation. Store slug history as needed; redirect to the current URL, avoid loops/chains and old-slug conflicts. |
| Canonical | Define the primary URL for equivalent path/parameter variants. Absolute URLs from trusted host/protocol config; never take arbitrarily from input headers, never canonicalize all content to the homepage. |
| HTTP status | Existing pages return 200; permanent URL change 301/308, temporary 302/307. Not found 404, permanently removed 410 when policy fits, server errors 5xx as appropriate. CRUD APIs use statuses per the contract (e.g. 201/204); never wrap every error in 200 or redirect error pages to the homepage. |
| Sitemap | Use canonical, public, published URLs meant for indexing; exclude drafts, noindex, redirects, errors and private pages. `lastmod` reflects meaningful changes, not request time. Batch/split sitemaps and cache by scale; check current limits when implementing. |
| Robots/index | Provide robots.txt and per-route robots data/headers; robots.txt controls crawling, not a substitute for noindex or authentication. Crawlers need access to read noindex; private pages must have authentication/authorization. |
| API/render | Return full content and metadata for frontend/SSR; public page URLs are directly accessible. Consistent validation, pagination and error contract; never return internal fields/secrets in serializers. |
| Query/cache | Avoid N+1, select needed fields, paginate with stable ordering, index per real queries. Cache keys separate tenant/language/permission when needed; never cache private content as public. Invalidate after commit on publish/update/delete/slug change, including related pages, metadata, sitemap and redirects. Measure before/after; never claim optimization from code alone. |
| Media | Check permission, size and the real file type, not just extension/client MIME. Safe storage names/keys, no executable uploads; manage alt and image variants as needed. Handle SVG/HTML per a safe policy, limit image-processing resources; never delete assets that are still referenced. |
| Multilingual | Implement only when real translations exist; manage URLs, slugs and translation relationships, clear fallback. Hreflang points to the matching public version with reciprocal links; never map every locale to one default page. |
| Security | Validate at the boundary, allowlist fields to prevent mass assignment, parameterize queries and control dynamic operators/sort. Sanitize CMS HTML with a maintained library, escape on render; never filter XSS with regex. CSRF per the auth mechanism, appropriate rate limits; never log secrets/PII. New routes require authentication by default, public routes must be declared explicitly. Hash passwords with the framework's dedicated algorithm (Argon2id/bcrypt/scrypt), never roll your own. Regenerate the session after login/privilege escalation, appropriate `Secure`/`HttpOnly`/`SameSite` cookies, logout invalidates the session/token server-side. CORS allowlists specific origins, never reflects the origin with credentials. User-supplied URLs (fetch/import/outbound calls) guard against SSRF: allowlist scheme/host, block internal/loopback/link-local IPs, re-check after redirects. Incoming webhooks must verify signature, timestamp, prevent replay and be handled idempotently. Disable debug/stack traces in production, never serve `.env`/`.git`/backups. |
| Operations | Log errors with context/request ID, never expose stack traces publicly. Bounded timeouts/retries, idempotency when operations can repeat; never retry every error. Use existing backup/monitoring, suggest restore checks when in scope; never claim backups are safe without verification. |
