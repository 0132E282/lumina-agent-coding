# Templates by document type

Read the registry and existing files per the rule at the top of the skill before choosing a template. A template is a frame to fill from verified sources, not finished content; replace all placeholders, drop inapplicable sections with a reason and update the menu in the same turn. Never overwrite existing schema, IDs or history to fit a template.

- [Markdown document](../assets/document-template.md): for `docs/**/*.md`; frontmatter is metadata, the Markdown body is `content`. README/AGENTS/CLAUDE keep their own conventions, not added to the catalog.
- [Repo-level testcase](../assets/repo-testcase-template.md): use at `docs/repo/<title-slug>-<yyyyMMdd>.md` when all tasks of an implementation plan are coded. Design only from real code/flows and record `Not Run`; update both `docs/repo/index.json` and `docs/index.json`.
- [Per-feature testcase](../assets/feature-testcase-template.json): minimal frame when `docs/testcases/index.json` does not exist yet. This file is suite/case/result data, not a menu. If a schema exists, map equivalent fields into it, keep IDs/history and old statuses; new cases are `Not Run`, fill `executedAt` with ISO 8601 only when actually run. Read the [testcase skill](../../testing/references/testcase.md) to design and reconcile.
- [Implementation plan](../assets/implementation-plan-template.json): frame for the agent assigned to write a plan, stored at `docs/plans/<title-slug>-<yyyyMMdd>.json`. Per [plan-format](../../../rules/docs.md#implementation-plan-contract), every task keeps all fields and `filesToChange` holds only verified paths; multi-record sections use objects with uniform fields, including `remainingRisks`. If a path is unclear, leave `[]` and record the blocker. `docs` only syncs/formats an existing plan, never devises solutions or switches to implementation; read [planner](../../../agents/planner.md) when assigned the planner role.
- [Menu JSON](../assets/menu-template.json): each entry only `title`, `description`, `tags`, repo-relative `path`. Applies to `docs/index.json`, `docs/repo/index.json`, `docs/plans/index.json`; the root catalog only points to Markdown docs. Never copy this menu into `docs/testcases/index.json`.

`<...>` is a placeholder; the creation date must be replaced with a date from a verified source, never inferred for old artifacts. Once the file to change is verified, fill `filesToChange` with objects like `{"path": "<repo-relative-path>", "changes": "<exact change>"}` and resolve the matching blocker. Before handoff, parse JSON, check metadata/links/TOC, menu fields, IDs and REQ/BR → AC → Task/Test traceability. Never run testcases just because a doc was created.
