# Frontend implementation requirements

Apply only the groups relevant to the assigned page type/scope; skip unrelated groups, do not expand scope.

| Group | How to apply |
|---|---|
| Semantic HTML | Use `header`, `nav`, `main`, `article`, `footer` in their proper roles. Headings follow content structure; never pick a heading level just for font size. Navigate with `<a href>`/router links that output anchors; actions use `<button>` with an appropriate `type`. |
| CSS/responsive | Follow project tokens and breakpoints; layout adapts to content on mobile/tablet/desktop, readable text, no full-page overflow. Tables/wide content get a sensible scroll area; never hide layout bugs with page-wide `overflow: hidden`. |
| JavaScript/forms | Handle loading, empty, success, error/retry, validation and pending submit. Avoid duplicate submits; keep form data on error. Decorative JavaScript or a broken widget must not lose the main content; handle race/stale responses appropriately. |
| Content/CMS | Render articles, images, tables, lists and rich text per the real data structure; fallbacks for missing images/data. Never use fake data to hide API errors. Format dates/prices/language per project requirements. |
| Metadata/SEO | Title, description, canonical and robots per route/data; use the framework's metadata/head API, avoid duplicate tags or stale-page metadata on navigation. Canonical is absolute and consistent between initial HTML/render; never canonicalize every page to the homepage. Never index admin/private content. |
| CSR/SSR/SSG | Identify which content is in the initial HTML and which needs JS. For public SEO pages, prefer server/static rendering when it fits the stack and update needs; never rewrite all CSR on your own. Avoid hydration mismatch, fetch waterfalls and calling browser APIs in server code. |
| Images/performance | Use appropriate size/format and `srcset`/`sizes` or the existing image component. Declare width/height or aspect ratio to reserve space. Lazy-load below-the-fold images, never lazy-load hero/LCP images; prioritize loading only truly important assets. Limit heavy scripts, split loading as needed and measure before concluding it is faster. |
| Accessibility | Native controls before ARIA; labels tied to inputs, understandable names for icon buttons, alt describing function (decorative images get empty alt). Clear keyboard/focus, never signal errors with color alone; dialogs manage focus and return it on close. Keep contrast, reduced motion and appropriate status announcements. |
| Navigation | Menus, breadcrumbs, pagination and internal links use real URLs; pages are reachable directly/on refresh. Infinite scroll has crawlable pagination URLs when SEO is needed. Nonexistent pages display properly and return 404 when the server/router supports it; never fake error pages with 200. |
| Sharing | Open Graph `og:title`, `og:description`, `og:image`, `og:url` and appropriate type per page; absolute, publicly accessible URLs/images. Prefer metadata in the HTML response for sharing crawlers; fall back to real data. |
| Render safety | Text uses the framework's escaping; CMS HTML needs a maintained sanitizer with an allowlist, never filter with regex or put raw HTML into the DOM. Control dangerous URL schemes, serialize JSON-LD safely; never expose secrets in bundles or HTML. CSP is an extra layer, not a substitute for sanitization. |
